# ADR-0002 — Body and feature model

- **Status:** Accepted 2026-10-09 (owner asked to proceed with M2 on the proposal); implemented in M2. How references actually work is in ADR-0003.
- **Date:** 2026-10-08
- **Prototype:** `prototypes/adr0002_chain.py` (results in `prototypes/adr0002_results.json`), reproducer `prototypes/tnp_repro.py`

## Context

The user should see documents → (optional) components → bodies, with one linear history for the whole document. A single feature may create, modify or consume several bodies (brief §3.6). The brief offers three mappings onto FreeCAD:

- (a) PartDesign Bodies managed by our command layer
- (b) Part-module feature objects with our own ordered history
- (c) a hybrid

## Prototype

The same chain was built on (a) and (b) in FreeCAD 1.1.4, headless: sketch rectangle 40 × 20 → extrude 10 → fillet R3 on the vertical edge at corner (40, 20). Then one edit was made per run. The check asks whether the fillet still sits at the intended corner (correct), fails with an explicit error (loud), or sits somewhere else without complaint (**silently wrong**). Every edit is one transaction; after it, a single undo must restore the original volume.

| model | edit | result | regen ms | undo restores |
|---|---|---|---|---|
| PartDesign | resize (drag the right edge +10) | error (loud) | 5.9 | yes |
| PartDesign | notch inserted upstream | correct | 25.8 | yes |
| PartDesign | extra side face next to the fillet | correct | 17.0 | yes |
| PartDesign | sketch deleted and redrawn | correct | 16.8 | yes |
| PartDesign | extrude length 10 → 12 | error (loud) | 4.3 | yes |
| Part | resize | error (loud) | 3.3 | yes |
| Part | notch inserted upstream | correct | 15.6 | yes |
| Part | extra side face | correct | 10.5 | yes |
| Part | sketch deleted and redrawn | correct | 9.0 | yes |
| Part | extrude length 10 → 12 | error (loud) | 3.0 | yes |

Median full-chain regeneration over 20 dimension edits: **PartDesign 4.8 ms, Part 2.9 ms**. In those runs the fillet had already failed after the first edit (see below), so this times sketch + extrude + a failing fillet.

### Finding

Both models use FreeCAD's element map, and both behave the same. The mapped names of the extrude's side edges (`#11:2;:G;XTR;…`) receive **new string-hash ids on every recompute**. A link to such an edge then survives only through FreeCAD's geometric fallback. That fallback works when the referenced edge itself is unchanged (notch, extra face, redraw), but **fails as soon as the referenced edge changes geometry**: even a plain extrude-length change breaks the fillet. It fails loudly ("Invalid edge link"), never silently wrong. A `Part::Box → Part::Fillet` chain does not show this, so the problem is specific to sketch-generated edges. `prototypes/tnp_repro.py` is a 30-line reproducer, suitable for an upstream report after a check against FreeCAD `main`.

Not tried, per the three-strikes rule in the brief: changing FreeCAD's hasher, or building the chain through GUI commands instead of the Python API.

## Decision

**(c) Hybrid: Part-module-based Kovač feature objects in one document-wide history, with our own reference records.**

1. Every user feature is a Kovač feature object (`Part::FeaturePython`) that computes its shape with OCCT/Part operations. Part::Extrusion- and Part::Fillet-style algorithms are reused as functions, not as separate document objects. Bodies are result shapes the history produces, not containers. That gives us no Body/Tip/one-solid rule to hide, and multi-body features work naturally.
2. The history is the ordered list of Kovač features, kept by the command layer (rollback marker, reorder with dependency checks, suppress).
3. **References are ours.** Each stored pick keeps three things:
   - a *semantic* name derived from our own features (e.g. "side edge generated by sketch vertex g2v2 in Extrude 3"; we know how our features generate topology)
   - FreeCAD's mapped name
   - a geometric signature: type, endpoints or centre, adjacent face normals

   Resolution tries them in that order and accepts only a unique match. Otherwise the feature shows an explicit broken-reference error with a re-pick flow. This directly fixes the measured weakness: the semantic name survives a length change, and the signature alone never decides when it is ambiguous.
4. PartDesign-only algorithms (e.g. hole and thread data) are called where useful, but PartDesign containers are not used.

Why not (a): PartDesign shows the same toponaming behaviour, runs about 70 % slower in this chain, and forces the Body/Tip/one-solid model the brief wants hidden.

Why not plain (b): plain Part objects inherit the same fragile references; the reference layer is what makes the difference.

## Consequences

- M2 builds the reference layer first, test-first against the toponaming torture suite (≥ 20 scenarios). The five edits above become its first cases.
- Undo is unaffected: everything stays inside FreeCAD transactions.
- Opening stock PartDesign documents still works (the tree shows their bodies, the timeline their features). Editing them through Kovač's flows is out of scope until a converter exists.
